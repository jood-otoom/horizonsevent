# Test strategy

## Automated checks

Run `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm build` from the root. The Vitest setup forces demo mode for component fixtures even when a developer's ignored `.env.local` selects live mode; tests that exercise the live read hook pass their live mode explicitly. Frontend tests cover branded routing, gauges, clock, demo values, mock controller records, retries, duplicate taps, rating bounds/averages, live aggregate validation, stale read fallback, Strict Mode's distinct Realtime channel topics, and the 1-of-1,200 MATCH progress display. Supabase tests use synthetic fixtures for the fixed b2match host/Bearer header, validated cursor pagination, deduplication, retries, registration/check-in rules, safe payload mapping, event/request validation, role checks, and origin rejection. Per-function `deno check index.ts` validates Edge TypeScript and pinned imports.

Correction unit/component tests cover a selected +3 undo, preserved history, an idempotent retry, a rejected second undo, rating-average recalculation, viewer-role payload boundaries, and a failed correction retry. A hook test verifies reconnect refetch and an update arriving during an active read. `supabase/verification/controller_corrections.sql` remains a rollback-only verification requiring an empty membership table; it has not run against the hosted project because the authorized account remains. A focused rollback-only hosted SQL probe exercised correction behavior before deployment. The browser rehearsal below verifies real Controller submission, audited undo, Realtime delivery, persistence, and a same-ID retry with the existing authorized account.

A local demo browser at `127.0.0.1:5177/controller` recorded +2, displayed 2, reversed that action, and displayed 0 with the original marked Reversed. After a reload, +1 followed by reversal likewise returned to 0, and a 4-star rating followed by reversal returned feedback count to 0 and average to “No ratings yet.” These observations exercise the new browser controls but use session-only synthetic state; they do not verify Supabase persistence or Realtime.

These unit tests do **not** prove SQL transactions, RLS, Auth integration, Realtime delivery, or hosted function behavior. The separate hosted checks below cover those paths with synthetic identities and records. No real participant data belongs in fixtures.

Before production, test with disposable authenticated sessions and, where appropriate, a local or preview project:

- Anonymous and unassigned users cannot read aggregates, memberships, sync logs, or records; viewers can read only event-safe values and cannot write.
- Staff/admin can submit +1/+2/+3 and ratings 1–5; viewer submissions fail. Direct browser inserts, updates, deletes, and service-only RPC calls fail.
- Repeated request IDs return the same result; conflicting payload reuse fails; simultaneous duplicate and distinct requests produce correct record and aggregate counts.
- A complete sync publishes snapshot/run/aggregate atomically. Page failure preserves the previous snapshot. Lease overlap, expiry, abandoned-run recovery, and old-run publication attempts cannot overwrite a newer result.
- Realtime sends only `dashboard_aggregates` changes to authorized members. Disconnect/reconnect triggers refetch; the 15-second fallback recovers missed events.
- The approved target is 1,200 in the hosted event 17135 setting and stays separate from actual meeting records. The currently approved 202/0 MEET publication is explicitly labeled a static snapshot with no automatic updates; a future automatic sync needs its own freshness and stale-state verification. No demo count appears in live mode.
- Run Supabase security and performance advisors, inspect grants, and test rollback with a database backup.
