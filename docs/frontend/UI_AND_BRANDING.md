# Dashboard UI and branding

## Public dashboard layout

`/` preserves the three existing metric components and data hook while following the owner-supplied KPI reference image. On a large screen it is a white, single-viewport composition: German Cooperation / EU funding artwork at the top-left, three MEET / MATCH / GROW columns across the left portion, event title and details on the far right, and the implementing partners along the bottom-left. Thin dividers stop at the information cards. `DashboardBackground` draws only the reference's top-right and bottom-right pink/red curves and gray dot clusters. The former header clock, tagline, photography, footer statement, and oversized petal background are absent from `/`; the controller retains its own layout and branding.

`PillarCard` shares the icon, heading, subtitle, gauge, and pale pink card structure. MEET uses an outlined three-person icon and "Connect with the right people"; MATCH uses outlined speech bubbles and "Find your perfect business partner"; GROW uses an outlined rising chart and "Scale with the right support". The shared SVG gauge clamps only its painted arc to 0–100%, keeps actual values intact, and uses the same arc center and radius for its marker; a small viewBox inset protects rounded caps from edge clipping. It does not paint a red segment or marker at zero. MATCH still displays completed meetings against the configured target with two-decimal target progress; GROW uses the stored rating average divided by 5 for the displayed percentage and labels its card "of Maximum Rating". No values or targets were moved into styling.

`EventInformation` presents New Horizons 2026, UJ Academy in Amman, the current Amman date, and a seconds-updating Amman time in aligned icon and text columns. It ends after the clock. Demo mode places its necessary "Demo values" label at the bottom of the dashboard. Connection indicators, snapshot verification, and publication time are absent from the presentation; data health remains in the existing hook and service. The 15-second aggregate refetch and Realtime-triggered refetch remain in place.

The desktop layout scales the supplied reference coordinates across 7:4 and 16:9 screens without document overflow. For the 7×4 meter LED display, the actual processor pixel resolution is still unconfirmed; 1792×1024 is the development preview, not a claim about the hardware. Funding/implementing artwork and KPI cards begin about 3% from the left edge, the funding artwork begins 3% from the top, and the event information block is offset 60px to the right of its reference position on desktop. Three equal grid columns keep gauges, central values, dividers, and card baselines aligned. Main figures, pillar headings, card labels, date, and location use bounded fluid sizes; a narrower desktop fallback reduces card figures and title width. The default `/` route is the event presentation view and requires no separate `?display=led` data or component path. Browser fullscreen or kiosk mode must be enabled by the operator. Below 1100px the layout becomes a two-column flow; below 700px it stacks each pillar and omits corner decoration so the marks and metrics stay readable. Motion is limited to gauge progress and loading state, with the existing reduced-motion CSS rule applied. The old footer networking photos are no longer referenced and were removed from source assets. At 1280×720, the exact 60px offset visibly clips the last part of “2026” at the right edge; the requested positioning leaves this narrow-desktop limitation until the title layout is separately adjusted.

## Staff controller prototype

`/controller` is a separate, mobile-first layout with a text-only header, bundled fonts, and existing red, cream, and deep-blue tokens. It has one MATCH card with a large session count and `+1/+2/+3` actions, and one GROW card with five explicit star buttons, rating submission, average, and feedback count. Stars and actions have at least 44×44 CSS-pixel touch targets, keyboard focus outlines, and visible disabled states. The controller uses no decorative animation and follows the global reduced-motion rule. The MATCH total label identifies a synthetic demo session; the live controller remains behind staff/admin Auth.

The controller starts empty in demo mode; it does not borrow the public dashboard's illustrative `428` and `4.4` fixture values. It now has +1/+2/+3 meeting actions and five rating choices. Submissions show pending, success, and error messages. A failed or uncertain submission retains its request ID and payload for safe retry; the GROW selection stays locked after an uncertain result. In live mode Supabase Auth and event membership protect the route and Edge endpoint, and successful actions persist before confirmation. The public display layout and brand are unchanged. A separate sign-in gate appears only in live mode before either route renders event data.

The collapsed Action History now shows at most five newest combined submissions, reversals, and check-in reconciliations when expanded. Clicking an eligible action's Undo button submits its reversal immediately, without a reason selector or confirmation step. The controller sends the existing `other` reason code for the backend audit record. A +2/+3 correction reverses that entire action; the operator can then enter the correct count through the ordinary buttons. Ratings work the same way and recalculate the average. Reversed actions remain visible. An uncertain result keeps the same correction request ID and payload for safe retry. The demo uses in-memory synthetic history; the live migration and updated Edge Function are deployed in the linked test project. The browser rehearsal verified two audited meeting corrections before the approved synthetic-row cleanup.

## Jordan startup map display

`/map` has two aligned white cards: the SVG Jordan choropleth and a compact statistics panel. The map fills about 58% of the two-card area. At the owner's request, the entire legend was removed, including its heading, color bar, numerical ranges, Fewer/More labels, and neutral-region key. The map uses the freed card space. The statistics card has one current-selection heading, one startup total, one separator, and the three programme stages. It contains no represented-governorate count or repeated selection row. The page uses the individual German Cooperation / EU logos above and GIZ / Ministry / ICON / PEM below, in that order. The same complete CSS dot grids used by `/` keep the existing corner decoration circular and unclipped. At 1792×1024 and 1366×768, the local preview had no document overflow; below 1100px the cards reflow, and below 700px they stack. The individual logos remain raster files and still need physical-screen inspection.

The map bundles [12 Jordan ADM1 regions](https://github.com/baselhusam/jordan-geo/blob/main/scripts/raw/jor-adm1.geojson) derived from [geoBoundaries](https://www.geoboundaries.org/api/current/gbOpen/JOR/ADM1/). The source metadata identifies a 2006 boundary year; acceptance of these boundaries for the event should be confirmed before release. The source derivative describes an ODbL attribution/share-alike obligation; the rendered footer includes attribution. The eight represented GeoJSON regions use the existing stable ISO-to-governorate mapping and are selectable through their polygons; the other four remain neutral and non-interactive. There are no map markers. Mouse hover changes the stroke subtly, native SVG titles show governorate totals on hover/focus, Enter/Space selects, and a region-shaped blue outline indicates the selection without changing its data fill. The data panel retains true zero stage counts.

`createHeatmapScale` ranks the **distinct** totals in the complete validated nationwide snapshot and assigns them, in ascending order, to at most six fixed sequential pink/red shades. Equal counts share a shade; higher counts never receive a lighter shade. The current published distribution creates six classes: 3–14, 23, 38, 44, 46, and 84 startups. A future all-equal distribution forms one middle-shade class; missing or invalid totals receive no red fill. The scale is memoized from the loaded snapshot and does not change when selection changes. Clicking a governorate or reset uses the in-memory snapshot and makes no selection-specific read.

The [earlier nationwide](screenshots/map-dashboard-live-1792x1024.jpg) and [earlier Aqaba](screenshots/map-dashboard-live-aqaba-1792x1024.jpg) captures document the superseded eight-dot design. The read-only local Vite captures show the [heat map at 1792×1024](screenshots/map-heatmap-nationwide-1792x1024.jpg), [Mafraq selected](screenshots/map-heatmap-mafraq-1792x1024.jpg), and the [heat map at 1366×768](screenshots/map-heatmap-nationwide-1366x768.jpg), using the linked test project's existing public aggregate. These captures predate removal of the legend. These are local previews, not a frontend deployment. No physical LED test has occurred.
