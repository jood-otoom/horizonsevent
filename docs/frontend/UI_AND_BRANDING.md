# Dashboard UI and branding

## Public dashboard layout

`/` preserves the three existing metric components and data hook while following the owner-supplied KPI reference image. On a large screen it is a white, single-viewport composition: German Cooperation and EU funding artwork at the top-left, the Ministry of Digital Economy and Entrepreneurship at the far right of the header, three MEET / MATCH / GROW columns across the left portion, event title and details on the far right, and the three implementing partners along the bottom-left. Thin dividers stop at the information cards. `DashboardBackground` leaves the top-right white and draws the existing lower-right pale curve and red outline with one four-petal flower. The former header clock, tagline, photography, footer statement, top-right graphics, and dot grids are absent from `/`; the controller retains its own layout and branding.

`PillarCard` shares the icon, heading, subtitle, gauge, and pale pink card structure. MEET uses the approved filled three-person PNG and "Connect with the right people"; MATCH uses two overlapping filled speech bubbles and "Find your perfect business partner"; GROW uses filled ascending bars and an upward arrow with "Scale with the right support". Each approved transparent PNG is centered within the existing pale circular KPI marker. The shared SVG gauge clamps only its painted arc to 0–100%, keeps actual values intact, and uses the same arc center and radius for its marker; a small viewBox inset protects rounded caps from edge clipping. It does not paint a red segment or marker at zero. MATCH still displays completed meetings against the configured target with two-decimal target progress. With a confirmed count of zero submissions, GROW has `averageRating:null` and uses the existing empty visual state (`0` and `0% Rating Achieved`); those presentation values are not a recorded zero-star rating. When feedback exists it displays the stored average and `(average / 5) × 100`. Its lower card shows the submission count beside "Feedback received". Missing or invalid feedback values display "Unavailable" rather than a false zero. MEET, MATCH, and GROW omit the word "Stale" from visible public labels and accessible names. A failed read still preserves the last valid values and internal freshness status; the controller retains its synchronization diagnostics.

`EventInformation` presents New Horizons 2026, UJ Academy in Amman, the current Amman date, and a seconds-updating Amman time in aligned icon and text columns. It ends after the clock. Demo mode places its necessary "Demo values" label at the bottom of the dashboard. The MEET gauge retains its published "Snapshot" label where applicable. None of the three public pillars adds a visible or screen-reader "Stale" suffix to retained values. The publication timestamp remains available in the data hook for diagnostics but is not printed on the public screen. Aggregate Realtime notifications, the 15-second public fallback, and browser-reconnection reads remain unchanged.

`AnimatedCounter` renders the numeric MEET checked-in, registered, and check-in-rate figures; MATCH completed meetings and target progress; and GROW feedback count, average rating, and rating achievement. It mounts at the first valid snapshot with the actual value, then compares each authoritative numeric prop with its previous value. Increases use a time-based cubic ease-out over 900ms by default, 1,000ms for MATCH, and 700ms for the decimal rating. A brief 1.06× number-only scale draws attention to increases. A new update cancels the old animation and starts from the number currently displayed; decreases and reduced-motion updates display the corrected value immediately. The counter formats with tabular numerals, US-style thousands separators, one decimal for nonzero ratings (`0` for an empty state), and the existing trimmed two-decimal MATCH percentage. No animation frames or scale effect run for unchanged data or clock rerenders. The public aggregate polling and reconnect behavior are unchanged; this presentation change does not add Realtime access.

The desktop layout scales the supplied reference coordinates across 7:4 and 16:9 screens without document overflow. For the 7×4 meter LED display, the actual processor pixel resolution is still unconfirmed; 1792×1024 is the development preview, not a claim about the hardware. Funding/implementing artwork and KPI cards begin about 3% from the left edge, and the funding artwork begins 3% from the top. The event information block starts at 74.7% of the viewport width with a bounded title size, keeping the complete year inside the right edge. Three equal grid columns keep gauges, central values, dividers, and card baselines aligned. Main figures, pillar headings, card labels, date, and location use bounded fluid sizes; a narrower desktop fallback reduces card figures and title width. On desktop viewports no taller than 700px, the gauges and dividers shorten and the metric cards move upward so the implementing logos stay clear. The default `/` route is the event presentation view and requires no separate `?display=led` data or component path. Browser fullscreen or kiosk mode must be enabled by the operator. Below 1100px the layout becomes a two-column flow; below 700px it stacks each pillar and omits corner decoration so the marks and metrics stay readable. Motion is limited to gauge progress, loading state, and changed KPI numbers, with reduced-motion behavior applied. The old footer networking photos are no longer referenced and were removed from source assets.

## Staff controller prototype

`/controller` is a separate, mobile-first layout with a text-only header, bundled fonts, and existing red, cream, and deep-blue tokens. It has one MATCH card with a large session count and `+1/+2/+3` actions, and one GROW card with five explicit star buttons, rating submission, average, and feedback count. Stars and actions have at least 44×44 CSS-pixel touch targets, keyboard focus outlines, and visible disabled states. The controller uses no decorative animation and follows the global reduced-motion rule. The MATCH total label identifies a synthetic demo session; the live controller remains behind staff/admin Auth.

The controller starts empty in demo mode; it does not borrow the public dashboard's illustrative `428` and `4.4` fixture values. It now has +1/+2/+3 meeting actions and five rating choices. Submissions show pending, success, and error messages. A failed or uncertain submission retains its request ID and payload for safe retry; the GROW selection stays locked after an uncertain result. In live mode Supabase Auth and event membership protect the route and Edge endpoint, and successful actions persist before confirmation. The public display layout and brand are unchanged. In live mode the sign-in gate appears only on `/controller`; `/` and `/map` open without a login screen.

The collapsed Action History shows at most five newest combined submissions, reversals, manual adjustments, and administrator operations when expanded. Clicking an eligible action's Undo button submits its reversal immediately, without a reason selector or confirmation step. The controller sends the existing `other` reason code for the backend audit record. A +2/+3 correction reverses that entire action; the operator can then enter the correct count through the ordinary buttons. Ratings work the same way and recalculate the average. Reversed actions remain visible. An uncertain result keeps the same correction request ID and payload for safe retry. The demo uses in-memory synthetic history; the live migration and updated Edge Function are deployed in the linked test project. The browser rehearsal verified two audited meeting corrections before the approved synthetic-row cleanup.
