# Dashboard UI and branding

## Public dashboard layout

`/` preserves the three existing metric components and data hook while following the owner-supplied KPI reference image. On a large screen it is a white, single-viewport composition: German Cooperation / EU funding artwork at the top-left, three MEET / MATCH / GROW columns across the left portion, event title and details on the far right, and the implementing partners along the bottom-left. Thin dividers stop at the information cards. `DashboardBackground` draws only the reference's top-right and bottom-right pink/red curves and gray dot clusters. The former header clock, tagline, photography, footer statement, and oversized petal background are absent from `/`; the controller retains its own layout and branding.

`PillarCard` shares the icon, heading, subtitle, gauge, and pale pink card structure. MEET uses an outlined three-person icon and "Connect with the right people"; MATCH uses outlined speech bubbles and "Find your perfect business partner"; GROW uses an outlined rising chart and "Scale with the right support". The existing `SemiCircularGauge` remains SVG-based, clamps only its painted arc to 0–100%, keeps actual values intact, and does not paint a progress marker at zero. MATCH still displays completed meetings against the configured target with two-decimal target progress; GROW uses the stored rating average divided by 5 for the displayed percentage. No values or targets were moved into styling.

`EventInformation` presents New Horizons 2026, 29 October 2026, and UJ Academy, Amman, Jordan. Beneath the event details, a compact status area distinguishes synthetic demo values, verified live MEET data, the one-time portal-verified MEET snapshot, stale/unavailable values, and MATCH/GROW connection states. The MEET publication time remains visible and is not presented as a continuously updating feed. Source/verification status logic and the 15-second aggregate refetch plus Realtime-triggered refetch remain in the existing hook and service.

The desktop layout scales the supplied reference coordinates across 7:4 and 16:9 screens without document overflow. For the 7×4 meter LED display, the actual processor pixel resolution is still unconfirmed; 1792×1024 is the development preview, not a claim about the hardware. Funding/implementing artwork and KPI cards begin about 3% from the left edge, the funding artwork begins 3% from the top, and the event title stays inside the right 3% safe area. Three equal grid columns keep gauges, central values, dividers, and card baselines aligned. Main figures, pillar headings, card labels, date, and location use bounded fluid sizes; a narrower desktop fallback reduces card figures and title width to prevent collisions. The default `/` route is the event presentation view and requires no separate `?display=led` data or component path. Browser fullscreen or kiosk mode must be enabled by the operator. Below 1100px the layout becomes a two-column flow; below 700px it stacks each pillar and omits corner decoration so the marks and metrics stay readable. Motion is limited to gauge progress and loading state, with the existing reduced-motion CSS rule applied. The old footer networking photos are no longer referenced and were removed from source assets.

## Staff controller prototype

`/controller` is a separate, mobile-first layout with the approved logo, bundled fonts, and existing red, cream, and deep-blue tokens. It has one MATCH card with a large session count and `+1/+2/+3` actions, and one GROW card with five explicit star buttons, rating submission, average, and feedback count. Stars and actions have at least 44×44 CSS-pixel touch targets, keyboard focus outlines, and visible disabled states. The controller uses no decorative animation and follows the global reduced-motion rule. Its footer and badge identify session-only synthetic values in demo mode and saved authorized records in live mode.

The controller starts empty in demo mode; it does not borrow the public dashboard's illustrative `428` and `4.4` fixture values. It now has +1/+2/+3 meeting actions and five rating choices. Submissions show pending, success, and error messages. A failed or uncertain submission retains its request ID and payload for safe retry; the GROW selection stays locked after an uncertain result. In live mode Supabase Auth and event membership protect the route and Edge endpoint, and successful actions persist before confirmation. The public display layout and brand are unchanged. A separate sign-in gate appears only in live mode before either route renders event data.

The correction UI shows the 12 most recent submissions beneath the cards. Staff select one action, choose a fixed reason, and explicitly confirm its undo. A +2/+3 correction reverses that entire action; the operator can then enter the correct count through the ordinary buttons. Ratings work the same way and recalculate the average. Reversed actions remain visible. An uncertain result keeps the correction request ID and reason for safe retry. The demo uses in-memory synthetic history; the live migration and updated Edge Function are deployed in the linked test project. The browser rehearsal verified two audited meeting corrections before the approved synthetic-row cleanup.
