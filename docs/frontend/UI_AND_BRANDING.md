# Dashboard UI and branding

## Public dashboard layout

`/` preserves the three existing metric components and data hook while following the owner-supplied KPI reference image. On a large screen it is a white, single-viewport composition: German Cooperation / EU funding artwork at the top-left, three MEET / MATCH / GROW columns across the left portion, event title and details on the far right, and the implementing partners along the bottom-left. Thin dividers stop at the information cards. `DashboardBackground` draws only the reference's top-right and bottom-right pink/red curves and gray dot clusters. The former header clock, tagline, photography, footer statement, and oversized petal background are absent from `/`; the controller retains its own layout and branding.

`PillarCard` shares the icon, heading, subtitle, gauge, and pale pink card structure. MEET uses an outlined three-person icon and "Connect with the right people"; MATCH uses outlined speech bubbles and "Find your perfect business partner"; GROW uses an outlined rising chart and "Scale with the right support". The shared SVG gauge clamps only its painted arc to 0–100%, keeps actual values intact, and uses the same arc center and radius for its marker; a small viewBox inset protects rounded caps from edge clipping. It does not paint a red segment or marker at zero. MATCH still displays completed meetings against the configured target with two-decimal target progress. GROW displays a rating of `0` and `0% Rating Achieved` only with a confirmed count of zero submissions, or the stored average and `(average / 5) × 100` when feedback exists. Its lower card shows the submission count beside "Feedback received". Missing or invalid feedback values display "Unavailable" rather than a false zero. Retained values after a failed read carry a compact "Stale" label.

`EventInformation` presents New Horizons 2026, UJ Academy in Amman, the current Amman date, and a seconds-updating Amman time in aligned icon and text columns. It ends after the clock. Demo mode places its necessary "Demo values" label at the bottom of the dashboard. The MEET gauge label now identifies a published static snapshot or stale retained value; MATCH and GROW label retained values stale. The publication timestamp remains available in the data hook for diagnostics but is not printed on the public screen. The 15-second public aggregate refetch remains in place and browser reconnection triggers another read. Public Realtime has been removed because the aggregate table is restricted to event members.

`AnimatedCounter` renders the numeric MEET checked-in, registered, and check-in-rate figures; MATCH completed meetings and target progress; and GROW feedback count, average rating, and rating achievement. It mounts at the first valid snapshot with the actual value, then compares each authoritative numeric prop with its previous value. Increases use a time-based cubic ease-out over 900ms by default, 1,000ms for MATCH, and 700ms for the decimal rating. A brief 1.06× number-only scale draws attention to increases. A new update cancels the old animation and starts from the number currently displayed; decreases and reduced-motion updates display the corrected value immediately. The counter formats with tabular numerals, US-style thousands separators, one decimal for nonzero ratings (`0` for an empty state), and the existing trimmed two-decimal MATCH percentage. No animation frames or scale effect run for unchanged data or clock rerenders. The public aggregate polling and reconnect behavior are unchanged; this presentation change does not add Realtime access.

The desktop layout scales the supplied reference coordinates across 7:4 and 16:9 screens without document overflow. For the 7×4 meter LED display, the actual processor pixel resolution is still unconfirmed; 1792×1024 is the development preview, not a claim about the hardware. Funding/implementing artwork and KPI cards begin about 3% from the left edge, and the funding artwork begins 3% from the top. The event information block starts at 74.7% of the viewport width with a bounded title size, keeping the complete year inside the right edge. Three equal grid columns keep gauges, central values, dividers, and card baselines aligned. Main figures, pillar headings, card labels, date, and location use bounded fluid sizes; a narrower desktop fallback reduces card figures and title width. On desktop viewports no taller than 700px, the gauges and dividers shorten and the metric cards move upward so the implementing logos stay clear. The default `/` route is the event presentation view and requires no separate `?display=led` data or component path. Browser fullscreen or kiosk mode must be enabled by the operator. Below 1100px the layout becomes a two-column flow; below 700px it stacks each pillar and omits corner decoration so the marks and metrics stay readable. Motion is limited to gauge progress, loading state, and changed KPI numbers, with reduced-motion behavior applied. The old footer networking photos are no longer referenced and were removed from source assets.

## Staff controller prototype

`/controller` is a separate, mobile-first layout with a text-only header, bundled fonts, and existing red, cream, and deep-blue tokens. It has one MATCH card with a large session count and `+1/+2/+3` actions, and one GROW card with five explicit star buttons, rating submission, average, and feedback count. Stars and actions have at least 44×44 CSS-pixel touch targets, keyboard focus outlines, and visible disabled states. The controller uses no decorative animation and follows the global reduced-motion rule. The MATCH total label identifies a synthetic demo session; the live controller remains behind staff/admin Auth.

The controller starts empty in demo mode; it does not borrow the public dashboard's illustrative `428` and `4.4` fixture values. It now has +1/+2/+3 meeting actions and five rating choices. Submissions show pending, success, and error messages. A failed or uncertain submission retains its request ID and payload for safe retry; the GROW selection stays locked after an uncertain result. In live mode Supabase Auth and event membership protect the route and Edge endpoint, and successful actions persist before confirmation. The public display layout and brand are unchanged. In live mode the sign-in gate appears only on `/controller`; `/` and `/map` open without a login screen.

The collapsed Action History shows at most five newest combined submissions, reversals, manual adjustments, and administrator operations when expanded. Clicking an eligible action's Undo button submits its reversal immediately, without a reason selector or confirmation step. The controller sends the existing `other` reason code for the backend audit record. A +2/+3 correction reverses that entire action; the operator can then enter the correct count through the ordinary buttons. Ratings work the same way and recalculate the average. Reversed actions remain visible. An uncertain result keeps the same correction request ID and payload for safe retry. The demo uses in-memory synthetic history; the live migration and updated Edge Function are deployed in the linked test project. The browser rehearsal verified two audited meeting corrections before the approved synthetic-row cleanup.

## Jordan startup map display

The local `/map` redesign keeps the existing funding-logo header, implementing-partner footer, dot decoration, and route boundaries. Inside their venue-safe content area, the Jordan SVG takes about 45% of the width and the right column about 55%. The right column places the startup total, gender/employment pair, connected Acceleration → Go to Market → Grow+ journey, and eight sector cards in that order. The 1792×1024 preview is the layout target; smaller desktops compress the cards and narrower screens reflow. The reference image is a layout and styling guide only: its 266 and other illustrative figures, castle/flag collage, and women-led/men-led wording are not used.

The map reuses the bundled [12 Jordan ADM1 regions](https://github.com/baselhusam/jordan-geo/blob/main/scripts/raw/jor-adm1.geojson) derived from [geoBoundaries](https://www.geoboundaries.org/api/current/gbOpen/JOR/ADM1/). Its source metadata gives a 2006 boundary year; geographic acceptance for the event remains pending. The ODbL attribution stays visible at the lower right. Eight governorates represented in the filtered workbook receive count-driven heat fills and one dimensional gradient pin each; the four other regions remain neutral context with no implied startup value. `mapGeometry` projects the polygons and places pins inside them. The SVG has no visible governorate text labels. Accessible region names, counts, and keyboard selection remain. The larger pins combine a white rim and center, inner highlight, red-to-burgundy body, and diffused pink halo. The selected pin renders above its neighbors with a stronger glow. The map remains enlarged slightly within its left panel without moving the header, footer, or decorative background.

`createHeatmapScale` ranks the distinct positive counts in the full bundled dataset and maps them across nine sequential luminous-pink-to-burgundy tints from `#FFF0F3` to `#9F0028`; equal values share a tint and the maximum always receives the deepest shade. This palette comes from the owner's new map-only visual reference and does not redefine the global brand tokens. Selecting a region keeps its count-based fill, brightens its red boundary and pin, and dims the other regions without hiding their borders. A polygon or pin click selects it; clicking it again, clicking elsewhere on the map page, or using Show all restores the national view. Polygon focus and Enter/Space work for keyboard access. The selected name appears once in the summary card; all five statistics components read the same selected aggregate in React state. The cards show zero stage/category counts rather than dropping categories. Percentage rounding uses largest remainders so the eight displayed sectors sum to 100%. Changed values use a brief number-only fade/slide and the gender bar transitions its proportions; unchanged values remain still. `prefers-reduced-motion` disables these effects.

The gender card labels the workbook's *participant gender* field. Its split bar uses a bright coral-to-red gradient for female participants and a crimson-to-burgundy gradient for male participants, with the owner's supplied glossy portraits on small pale contrast backings and large white percentages. A small segment hides its icon to keep the percentage readable, and a zero segment retains a visible 0% in its label. The employment card uses the same paired gradients and matching supplied building and people artwork. It counts known `Employees > 0` startups and sums known `Employees` values, rather than column S's different total-current-employment measure. The two Amman employment entries flagged missing in column X remain documented in [the workbook integration guide](../integrations/MAP_WORKBOOK.md); their warning is omitted from the venue-facing card. The static aggregate is bundled into the frontend; map selection makes no network request. Existing hosted Supabase map data remains historical and is not changed by this local redesign.

All five outer cards share fine rose borders, consistent radii, soft shadows, and light surfaces, while the inner graphics carry the vivid color. The three stage arrows form one journey with a crimson → coral-red → luminous blush gradient progression and supplied pictograms; zero counts remain visible. Sector backgrounds use each displayed percentage relative to the highest visible sector percentage. A light ramp covers lower shares and a deep crimson ramp covers shares at least 75% of the maximum; that gap avoids low-contrast middle shades. Text switches to white on the deep ramp; each red/pink icon remains legible on its pale backing. A displayed 0% stays in the lightest blush.

`MapIcon` is the reusable 15-subject card icon component. It displays the owner's standalone [female portrait](../../frontend/src/assets/map/icons/female-portrait.png) and the remaining subjects from the matching [4×4 icon sheet](../../frontend/src/assets/map/icons/dashboard-icon-sheet.png) inside a 64-unit SVG viewport. Decorative instances are hidden from assistive technology; the component accepts an accessible label when an icon conveys meaning on its own. This owner-supplied artwork replaces the earlier hand-drawn filled SVG paths without changing card data or interactions.
