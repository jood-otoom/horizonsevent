## Local development

Install Node.js 22.12+, pnpm 11.25.0, Docker Desktop, and Supabase CLI 2.120.0. The CLI can be run without a global install as `pnpm dlx supabase@2.120.0`. Docker and a running local Supabase database were unavailable during this change.

1. Run `pnpm install --frozen-lockfile`. For credential-free demo, run `pnpm dev` and leave `VITE_DATA_MODE=demo`.
2. For a **disposable local database**, run `pnpm dlx supabase@2.120.0 start`, then `pnpm dlx supabase@2.120.0 db reset --local --no-seed`. The reset deletes local data; do not use `--linked` or a hosted URL.
3. Run `pnpm dlx supabase@2.120.0 functions serve`. Put the exact Vite origin (for example `DASHBOARD_ALLOWED_ORIGINS=http://127.0.0.1:5176` when Vite runs on port 5176), `B2MATCH_EVENT_ID=17135`, and `B2MATCH_SYNC_ENABLED=false` in an ignored `supabase/functions/.env` file. No b2match key is needed to test controller/aggregate access.
4. Create a local Auth user in Studio and grant its UUID a membership using a reviewed local SQL statement, for example `insert into public.event_memberships(event_id,user_id,role) values (17135, '<LOCAL_USER_UUID>', 'staff');`. Set `VITE_DATA_MODE=live`, `VITE_SUPABASE_URL`, and `VITE_SUPABASE_PUBLISHABLE_KEY` in ignored `frontend/.env.local`, using values from local `supabase start`.
5. Run `pnpm dev`; sign in on `/` or `/controller`. The private dashboard shows no MEET total until a complete sync. Test `dashboard-data` with viewer/staff/admin sessions, `controller-submit` with staff/admin, and anonymous/unauthorized rejection. Exercise Realtime and the 15-second read fallback.

For local Edge type checks, run `deno check index.ts` from each of the three function directories. Function dependencies are pinned in each `deno.json` and `deno.lock`.
